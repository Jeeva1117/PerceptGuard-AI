# PerceptGuard AI — Predictive Early Warning Data Contract Specification

**Document Version:** 1.0.0  
**Phase:** Day 10 Architecture & Data Ingestion Specification  
**Status:** Approved  

---

## 1. Overview & Purpose

The **Early Warning Data Contract** defines the strict, standardized schema governing prediction data consumed by the PerceptGuard AI Risk Assessment and Early Warning system.

It guarantees that all upstream forecasts generated by the deep learning recurrent pipeline (`LSTMForecaster`) or baseline models are validated, structurally uniform, range-bounded, chronologically consistent, and leak-free before entering the risk evaluation pipeline.

---

## 2. Standardized Field Specification: `EarlyWarningInputRecord`

| Field Name | Type | Mandatory? | Default Value | Valid Range / Allowed Values | Description |
| :--- | :--- | :---: | :--- | :--- | :--- |
| `prediction_id` | `str` | Yes | Auto-derived | Non-empty string | Unique prediction identifier (e.g. `{sequence_id}_H{horizon}`) |
| `sequence_id` | `str` | Yes | — | Non-empty string | Identifier of the historical feature sequence |
| `source_frame_id` | `str` | Yes | — | Valid frame filename | Filename of the final observed history frame (e.g. `frame_000005.jpg`) |
| `target_frame_id` | `str` | Yes | — | Valid frame filename | Filename of the predicted future target frame (e.g. `frame_000008.jpg`) |
| `horizon` | `int` | Yes | — | $\{1, 3, 5\}$ | Forward forecast horizon in frames |
| `predicted_reliability` | `float` | Yes | — | $[0.0, 1.0]$ | Continuous predicted detection reliability score |
| `source_frame_index` | `int` | Optional | `None` | $\ge 0$ | Zero-indexed source video frame position |
| `target_frame_index` | `int` | Optional | `None` | $> \text{source\_frame\_index}$ | Zero-indexed target video frame position |
| `target_timestamp_seconds`| `float` | Optional | `None` | $\ge 0.0$ | Physical video presentation timestamp in seconds |
| `track_id` | `int` | Optional | `None` | $\ge 0$ | Object tracking identifier (when track-level forecasting is active) |
| `model_name` | `str` | No | `"LSTMForecaster"` | String | Name of the forecasting model producing the prediction |
| `checkpoint_id` | `str` | No | `"unknown"` | String | Name or hash of the trained model checkpoint |
| `experiment_id` | `str` | Optional | `None` | String | Experiment tracking identifier |
| `prediction_status` | `str` | No | `"success"` | `{"success", "failed", "unavailable", "degraded"}` | Execution status of the inference stage |
| `inference_time_ms` | `float` | No | `0.0` | $\ge 0.0$ | Time taken in milliseconds to execute inference |
| `alignment_method` | `str` | No | `"metadata_exact"` | String | Method used to align sequence metadata with future frames |
| `dataset_id` | `str` | Optional | `None` | String | Dataset source identifier (e.g. `driving_sample`) |
| `video_id` | `str` | Optional | `None` | String | Video source identifier |
| `created_at` | `str` | No | UTC ISO 8601 | ISO 8601 string | Creation timestamp of the record |

## 3. Compatibility with Day 9 Forecasting Artifacts

The Early Warning contract is **100% backward-compatible** with Day 9 prediction outputs:
1. **Direct Ingestion:** The `EarlyWarningInputRecord.from_day9_record()` method accepts both `HorizonPredictionRecord` objects and raw dictionary entries from Day 9's `predictions.json` artifacts.
2. **Field Normalization:** 
   - `input_end_frame` is mapped to `source_frame_id`.
   - `target_frame_reference` is mapped to `target_frame_id`.
   - `input_end_source_frame_index` is mapped to `source_frame_index`.
   - `target_source_frame_index` is mapped to `target_frame_index`.
3. **Automated Verification:** Ingestion of the full Day 9 prediction artifact (`experiments/forecasting/multi_horizon/official_multi_horizon_run/predictions.json`, 414 records across 138 sequences) was verified with a **100% validation pass rate (0 errors)**.

## 4. Contract Validation Rules

Each ingested record must satisfy the following invariant assertions:

1. **Mandatory Fields:** `sequence_id`, `horizon`, and `predicted_reliability` must be non-null and correctly typed.
2. **Horizon Invariant:** Horizon must reside in $\{1, 3, 5\}$. Unsupported integer horizons (e.g., $H=2, 7$) or negative horizons are rejected.
3. **Probability Bounding:** `predicted_reliability` must satisfy:
   $$0.0 \le \hat{R} \le 1.0, \quad \hat{R} \notin \{\text{NaN}, \pm\infty\}$$
4. **Temporal Ordering:** If source and target frame indices are provided, target must be strictly ahead in time:
   $$\text{target\_frame\_index} > \text{source\_frame\_index}$$
5. **Status Integrity:** `prediction_status` must belong to the approved vocabulary (`{"success", "failed", "unavailable", "degraded"}`).

## 6. Error Handling & Exception Hierarchy

- **`EarlyWarningDataContractError`**: Raised when raw input parsing fails, mandatory fields are missing, or unparseable data types are supplied.
- **Validation Errors List**: The `validate()` method returns a non-throwing list of descriptive string errors, allowing batch validation to collect all defects without aborting pipeline execution.
