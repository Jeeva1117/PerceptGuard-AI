# PerceptGuard AI — Multi-Horizon Forecasting Engine
## Technical Specification, Horizon Alignment & CPU Inference Architecture

---

## 1. Executive Summary

This document specifies the architecture, horizon alignment mechanics, prediction schema, and CPU-optimized inference workflow of the **Multi-Horizon Forecasting Engine** (`MultiHorizonForecaster`) implemented for **Day 6 Task 5**.

The engine operates on historical perception sequences ($L \in \{5, 10, 15, 20\}$ with $F = 27$ engineered features) to forecast future object-detection reliability across multiple forward time horizons:
- **Horizon 1 ($h = 1$):** Forecast reliability for frame $t + 1$
- **Horizon 3 ($h = 3$):** Forecast reliability for frame $t + 3$
- **Horizon 5 ($h = 5$):** Forecast reliability for frame $t + 5$

The system is optimized for CPU execution (Intel Core i3, 8 GB RAM, Windows 11) using `torch.inference_mode()`, memory-bounded chunked batch processing, and exact frame-to-horizon temporal mapping.

## 3. Checkpoint Requirements & Compatibility Validation

`MultiHorizonForecaster` requires a valid checkpoint dictionary generated by `CheckpointManager`:

| Key | Expected Type | Validation Criteria |
| :--- | :--- | :--- |
| `model_state_dict` | `OrderedDict` | Must contain matching weights for `lstm` and `fc` projection head. |
| `input_size` | `int` | Must strictly equal 27 (matches Day 5 feature count). |
| `hidden_size` | `int` | Must match model hidden dimension (default 32, $\ge 4$). |
| `output_horizons` | `List[int]` | Must strictly equal `[1, 3, 5]`. |
| `experiment_id` | `str` | Identifier tracked as `checkpoint_id` in prediction records. |

If a checkpoint file is missing, corrupted, or exhibits feature/horizon dimension mismatches, the engine halts with `MultiHorizonForecastingError`. It never silently modifies input tensors or weights.

## 4. Horizon Alignment & Frame Index Handling

Temporal alignment must never assume consecutive frame numbers. The engine employs a 3-tier resolution strategy:

1. **`metadata_exact` (Primary Strategy)**:
   Extracts pre-computed horizon metadata from the Day 5 `SequenceDatasetRecord` (e.g. `target_frame_id`, `target_source_frame_index`, `target_timestamp_seconds`). This guarantees exact alignment with actual video frames.
2. **`frame_index_offset` (Secondary Strategy)**:
   When a chronological list of available frame records is provided, the current frame index is located, and the target is resolved at offset `current_index + horizon`. Handles non-continuous frame drops gracefully.
3. **`sequential_extrapolation` (Fallback Strategy)**:
   Extracts frame numbers via regex (`frame_(\d+).ext`), projects target frame number `frame_num + horizon`, and calculates expected timestamp offsets ($\Delta t = h \times 0.1994\text{s}$).

Each prediction record explicitly logs its `alignment_method` (`metadata_exact`, `frame_index_offset`, `sequential_extrapolation`, or `out_of_bounds`).

## 6. Prediction Artifact Structure

Prediction outputs are organized under `experiments/forecasting/multi_horizon/<run_id>/`:

| Artifact File | Description |
| :--- | :--- |
| `predictions.json` | Complete array of all prediction records across all sequences and horizons. |
| `horizon_1_predictions.json` | Filtered array containing only $h=1$ predictions ($t+1$). |
| `horizon_3_predictions.json` | Filtered array containing only $h=3$ predictions ($t+3$). |
| `horizon_5_predictions.json` | Filtered array containing only $h=5$ predictions ($t+5$). |
| `prediction_summary.json` | Aggregated volume counts, horizon distributions, and timing statistics. |
| `model_metadata.json` | Model architecture summary (parameters, hidden units, layers, activation). |
| `feature_manifest.json` | Ordered feature names ($F=27$) and dimensions. |
| `inference_metadata.json` | Host platform, runtime environment, Python/PyTorch versions, CPU threads. |
| `errors.json` | Recorded exceptions or corrupted sequence telemetry (when errors occur). |

*Note: Evaluation metrics (accuracy, MAE, RMSE) are deliberately omitted from the summary as they belong to Task 6.*

## 7. Command-Line Interface (CLI)

The inference CLI is invoked via `python -m src.forecasting.multi_horizon_forecaster`:

```powershell
python -m src.forecasting.multi_horizon_forecaster --help
```

### CLI Arguments
- `--input <path>`: Path to Day 5 sequence directory (default: `datasets/processed/driving_sample/features/sequences/run_official`).
- `--checkpoint <path>`: Path to trained LSTM checkpoint file (`.pt`).
- `--config <path>`: Path to YAML configuration (default: `config/forecasting_config.yaml`).
- `--horizons <int...>`: Forecast horizons to predict (default: `1 3 5`).
- `--batch-size <int>`: Batch size for inference (default: 8).
- `--device {cpu,cuda}`: Inference device (default: `cpu`).
- `--sequence-length <int>`: Sequence length to evaluate ($L \in \{5, 10, 15, 20\}$).
- `--output <dir>`: Destination folder for output artifacts.
- `--max-sequences <int>`: Optional limit on sequences processed.
- `--verbose`: Enable detailed logging.

## 8. CPU Optimization & Performance

- **Inference Mode**: Forward passes run inside `with torch.inference_mode():`, which disables autograd tracking, version counter increments, and view tracking.
- **Batch Processing**: Chunked batches ($B=8$ or $B=16$) prevent loading all sequence arrays into memory at once.
- **Dynamic Memory**: Memory overhead is strictly $< 50\text{ MB}$ RSS on CPU.
- **Inference Latency**: Benchmarked at $\approx 0.055\text{ ms}$ per sample ($> 18,000$ predictions/sec) on Intel Core i3 CPU.

---

## 9. Ground-Truth Requirements & Known Limitations

1. **Model Checkpoint Dependency**: Real-world forecasting requires a trained checkpoint resulting from supervised training with verified ground-truth reliability targets.
2. **Monocular Visual Input**: Forecasts are conditioned on camera-derived detection, motion, and visual quality features. Severe sensor occlusion exceeding historical window length $L$ may limit predictive reliability.
3. **Task 5 Scope Boundary**: Model evaluation metrics (MAE, RMSE, R2) and residual analyses are strictly reserved for Day 6 Task 6.
